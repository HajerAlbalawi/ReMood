---
name: AI provider setup fallback
description: Replit AI Integration availability and the safe direct-provider fallback for AI features.
---

When Replit AI Integration provisioning is unavailable, AI features should retain a direct-provider fallback and fail gracefully when no valid provider credentials are available.

**Why:** Some workspaces can reject integration provisioning because of account or access restrictions, and an invalid provider value must not be sent as an Authorization header.

**How to apply:** Prefer the managed integration when its base URL is present; otherwise validate the direct provider configuration and return a user-facing unavailable state without changing deterministic recommendations.

For book discovery previews, provider failure should return a validated local-library preview when possible, clearly labelled as free/local rather than pretending it was generated by AI; the ordinary recommendation flow remains unchanged.

**Why:** The book assistant is still useful in workspaces where AI provisioning is restricted, and a 503 left users with no preview even though ReMood already had a curated library.

**How to apply:** Keep the AI path first, then fall back only on provider or response failures. Preserve language, exclusions, reading-length intent, and the preview response shape so the existing UI can render it safely.

Natural-language age constraints in book requests should be treated as hard filters when they are explicit; “this month” is a reading-context hint unless the user explicitly ties it to publication or release.

**Why:** A broad “classic” match can still violate a request such as “older than 100 years,” while treating every mention of the current month as a publication-month filter can remove useful valid choices.

**How to apply:** Extract age/year and explicit publication-month constraints before ranking, return verified publication metadata, and use a round plus temporary exclusions for genuinely different alternatives.
